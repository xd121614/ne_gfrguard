# GF2000 AR 需求规格说明书

## 1. 概述 (Overview)

### 1.1. 背景与目标 (Background & Goal)

**背景**：勒索软件是全球企业面临的最严重安全威胁之一。在 NAS（网络附加存储）场景中，Windows 客户端感染勒索软件后，通过 SMB 协议对 NAS 上的共享文件进行覆盖式加密和破坏。传统基于主机 Agent 的 EDR 方案无法保护不可安装 Agent 的 NAS 设备，形成了防护盲区。

**核心问题**：如何在不修改 Samba 源码、不侵入客户端的前提下，在 NAS 端检测并阻断来自 SMB / FTP / 云同步 / 本地进程四种通道的勒索软件行为，同时将正常业务操作的误报控制在可接受范围内。

**产品目标**：构建一套多层次的 NAS 反勒索防护系统，覆盖 SMB 共享（VFS 层）、云连携（Google Drive / OneDrive）、FTP 、本地四种数据通道，通过文件操作拦截、内容分析、行为评分和会话阻断，实现对共享文件数据的实时保护。

**业务价值**：

- 为 NAS/Samba 文件服务器提供透明的反勒索保护，无需客户端安装任何软件
- 支持完全私有化部署，满足数据主权和合规要求
- 基于行为分析和内容检测的组合策略，相比纯签名方案适应性更强
- 统一覆盖 SMB、云同步、FTP、本地四种主流文件访问通道

### 1.2. 关键成功指标 (Success Metrics)

| 指标                   | 目标值           | 衡量方式                                                           |
| ---------------------- | ---------------- | ------------------------------------------------------------------ |
| 已知勒索软件行为检出率 | ≥90%            | 勒索软件模拟测试（赎金信写入、批量加密、批量重命名），覆盖四个通道 |
| 正常业务操作误报率     | <5%              | 正常文件部署、配置更新、批量编辑不触发阻断                         |
| 性能开销               | 不增加可感知延迟 | 启用防护前后各通道读写延迟对比                                     |
| 系统稳定性             | 0 次业务进程崩溃 | 连续 7×24 小时压力测试（smbd/vsftpd/rclone 无崩溃）               |

### 1.3. 范围 (Scope)

**包含的核心功能**：

| 模块             | 通道                    | 拦截技术                                                        |
| ---------------- | ----------------------- | --------------------------------------------------------------- |
| VFS 反勒索模块   | SMB                     | Samba VFS 回调 (gf_openat 等)                                   |
| 策略守护进程     | 全部                    | epoll (VFS socket + fanotify fd)                                |
| FTP 反勒索模块   | FTP                     | fanotify FAN_OPEN_PERM + /proc/PID 上下文关联                   |
| 云连携反勒索模块 | Google Drive / OneDrive | fanotify FAN_OPEN_PERM + rclone cmdline 解析                    |
| 本地反勒索模块   | 本地进程                | fanotify FAN_OPEN_PERM + PID/comm 粒度                          |
| 文件恢复工具     | 全部                    | gfrguard-recover CLI                                            |
| 规则升级工具     | 全部                    | gfrguard-rule-update CLI（签名校验 + 原子替换 + SIGHUP 热生效） |
| 配置系统         | 全部                    | JSON + SIGHUP 热重载 + 四通道子开关                             |

## 2. 用户故事与场景 (User Stories & Scenarios)

### 2.1. 用户画像 (Persona)

| 角色                      | 描述                                    | 核心关注点                                           |
| ------------------------- | --------------------------------------- | ---------------------------------------------------- |
| **IT 系统管理员**   | 管理企业 NAS/Samba 文件服务器的运维人员 | 部署简便、不破坏现有服务、清晰的日志和告警           |
| **安全运维工程师**  | 负责企业安全策略和事件响应的安全人员    | 检测准确率、误报率可控、阻断后可恢复、新威胁快速响应 |
| **开发/测试工程师** | 构建和验证 GFRGuard 功能的工程人员      | 配置灵活、调试信息充分、可复现的测试框架             |

### 2.2. 用户故事 (User Stories)

**故事一：勒索软件批量加密检测与阻断（SMB 通道）**

> 作为一个 IT 系统管理员，当 Windows 客户端被勒索软件感染并通过 SMB 向 NAS 写入加密文件时，我希望系统能自动检测到异常行为（高熵值、批量重命名为勒索扩展名、写入赎金信），并及时阻断该客户端会话并自动恢复被篡改的文件。

**故事二：正常业务操作不受影响**

> 作为一个 IT 系统管理员，当用户批量部署配置文件或更新软件包（相同内容覆盖多个目录）时，我希望系统能识别这是正常操作而非勒索行为，不触发阻断。

**故事三：配置策略灵活调整**

> 作为一个安全运维工程师，当业务环境发生变化时，我希望能通过修改 JSON 配置文件并发送 SIGHUP 信号来热重载所有策略参数，而不需要重启任何服务。

**故事四：文件被勒索后快速恢复**

> 作为一个 IT 系统管理员，当系统检测到勒索行为并自动阻断会话后，我希望能通过简单的命令从备份区恢复被篡改的文件，并同时清理勒索软件创建的加密文件和赎金信。

**故事五：多通道统一防护**

> 作为一个安全运维工程师，当企业同时使用 SMB 共享、云同步（Google Drive / OneDrive）和 FTP 三种文件访问方式时，我希望系统能在所有通道上提供一致的勒索行为检测和阻断能力，以便消除任一通道的防护盲区。

**故事七：按需启用防护通道**

> 作为一个安全运维工程师，我希望能通过配置总开关统一控制防护策略的启停，并可独立开关各通道（SMB / 云连携 / FTP / 本地），关闭不需要的通道以减少系统资源开销。

**故事八：保护范围精准控制**

> 作为一个安全运维工程师，我希望能指定保护的文件类型和例外文件/文件夹列表，使系统仅对真正重要的文件进行监控和备份。

**故事九：NAS 本地进程勒索行为检测**

> 作为一个安全运维工程师，当 NAS 上运行的某个进程（如备份脚本被篡改、第三方服务被植入恶意代码）直接在本地文件系统上执行批量加密或删除操作时，我希望系统能检测到该进程的异常行为（按 PID/进程名粒度追踪），并及时暂停或终止该进程。

**故事十：FTP 文件传输勒索检测**

> 作为一个安全运维工程师，当攻击者通过 FTP 协议向 NAS 上传加密文件或批量覆盖已有文件时，我希望系统能像 SMB 通道一样自动检测异常并阻断该 FTP 会话。

**故事十一：云同步加密文件传播阻断**

> 作为一个安全运维工程师，当客户端被勒索软件感染后加密文件通过云同步（如 OneDrive）扩散到 GF2000 设备时，我希望系统能检测到同步任务中的异常文件变更，并自动暂停该同步定时任务，防止加密文件进一步扩散。

## 3. 功能性需求 (Functional Requirements)

### 3.1. 基本设置

- 进行勒索攻击防护功能的启用/禁用设置（总开关），以及各功能防护项目的启用/禁用设置。（GF2000本体勒索防护、SMB勒索防护、云联动勒索防护、FTP勒索防护）
- 设置检测到勒索软件时的动作。可选择文件自动恢复或手动恢复
- 设置勒索攻击防护的对象文件类型，防护指定类型的文件
- **通过邮件通知设置，在发生勒索软件事件时进行邮件通知**
- 通过版本信息显示，显示当前使用中的引擎及规则的版本

**FR-BASIC-CONFIG-01: **勒索攻击防护****

- **描述**：进行勒索软件攻击防护功能的启用/禁用设置（总开关）及各独立防护项目的启用/禁用设置。（GF2000本体勒索软件防护、SMB勒索软件防护、云联动勒索软件防护、FTP勒索软件防护）
- **需求**：
  - 设置为"启用"时，勒索软件攻击防护功能启用，以下4个独立防护项目可分别设置启用/禁用。独立防护项目包括：GF2000本体勒索防护、SMB勒索防护、云联动勒索防护、FTP勒索防护。
  - 设置为"启用"时，【黑名单/白名单】及【例外设置】功能启用
  - 设置为"禁用"时，勒索软件攻击防护功能禁用，上述独立防护项目无法设置
  - 设置为"禁用"时，【黑名单/白名单】及【例外设置】功能禁用
- **优先级**：P0

**FR-BASIC-CONFIG-02: **勒索软件病毒检测后的动作****

- **描述**：勒索软件攻击防护功能检测到勒索软件动作后，按照已设置的文件恢复方式恢复文件。
- **需求**：
  - 阻断勒索软件攻击动作（初始设置·不可更改）
  - 勒索软件检测后的动作设置：自动恢复文件（默认），或手动恢复文件
  - 文件自动恢复：检测到勒索软件时，从安全备份区域恢复被更改的文件，并将勒索软件新建的文件移动到隔离区
  - 自动恢复的处理结果记录到【事件记录】→【勒索软件检测日志】→【已处理事件】中
  - 手动恢复文件：检测到勒索软件时，不执行文件恢复处理，仅阻断攻击动作。文件恢复由用户手动执行
  - 手动恢复的处理结果记录到【事件记录】→【勒索软件检测日志】→【已处理事件】中
- **优先级**：P0

**FR-BASIC-CONFIG-03: **防护对象文件类型****

- **描述**：勒索软件攻击防护引擎保护指定类型的文件，对未指定类型的文件不进行勒索软件防护。
- **需求**：
  - 默认防护指定的文件类型
  - 选择"指定的文件类型"时，仅防护已设置的文件类型
  - 扩展名列表：7z, ai, bmp, cer, cfg, chm, crt, csv, dcm, der, doc, docx, dotm, dotx, dwg, efi, eps, gif, hwp, hwpx, jbw, jpeg, jpg, jps, jtd, key, lic, lnk, mp3, nc, odp, ods, odt, ogg, one, ost, p12, p7b, p7c, pdf, pef, pem, pfx, png, ppt, pptx, psd, pst, ptx, rar, rdp, rtf, srw, tap, tif, tiff, txt, uti, x3f, xls, xlsb, xlsm, xlsx, xps, zip，exe，mp4，m4a，avi
- **优先级**：P0

**FR-BASIC-CONFIG-04: 邮件通知**

- **描述**：勒索软件防护引擎检测到攻击动作时，发送邮件通知。
- **需求**：
  - **开关读取方式由SAXA提供**
  - 勒索软件防护引擎检测到攻击动作时，向指定的目标地址发送邮件通知
  - 按预定义的间隔（5分钟）发送邮件通知
  - 5分钟间隔内未发生勒索软件事件时不发送
  - 邮件主题：【来自hostname的通知】检测到勒索攻击
  - 发送目标：
    - 可指定用户组
    - 向作为指定用户组所属用户信息而设置的邮件地址发送邮件
    - 指定用户组所属的所有用户均未设置邮件地址时，中止邮件发送
  - 通知邮件发送失败时，以10分钟为周期最多重试3次
  - 达到最大重试次数邮件发送仍失败时，中止通知
  - 设备重启时，邮件发送未完成的通知任务将被删除
  - 通知邮件发送目标（沿用GF2000［事件通知］）
  - 通知内容：

  ```
  致正在使用**hostname**的用户

  勒索攻击防护检测到了病毒。
  强烈建议对公司内部PC进行病毒检查。

  检测事件数：xx
  （显示最近的前10条事件信息）

  事件1 (YYYY-MM-DD hh:mm:ss)：
  ·检测类型：xxx
  ·用户：xxx
  ·客户端IP：xxx.xxx.xxx.xxx
  ·风险评分：xx
  ·恢复类型：自动/手动/-
  ------------------------------
  事件2
  …
  注）请勿回复本邮件。
  ```
- **优先级**：P0

**FR-BASIC-CONFIG-05: **版本信息****

- **描述**：显示GF2000使用中的勒索软件攻击防护引擎版本及当前规则库版本。
- **需求**：
  - 引擎版本的显示形式：x.x.x
  - 规则库版本的显示形式：x.x.x
  - 勒索软件攻击防护引擎或规则库更新时，显示中的版本信息也随之更新
- **优先级**：P2

以下为基本设置的关键内部支撑需求（非页面需求）：

**FR-BASIC-CONFIG-06: JSON 配置管理**

- **描述**：全系统使用全局唯一配置文件 rguard-policy.json 统一管理全部策略：全通道顶层策略、protection 开关、ftp/cloud_sync/local 模块配置、whitelist/blacklist/exceptions/file_extensions 等集中在一处，避免多配置文件分散导致的不一致与维护负担。页面上所有设置项（基本设置、黑白名单、例外设置等）最终都落到该文件。
- **需求**：
  - 所有参数均有默认值，最小配置即可运行（仅需配置 fanotify 监控路径）
  - 配置项覆盖四通道开关、监控路径、名单、例外、保护文件类型、发现勒索病毒后动作
- **优先级**：P0

**FR-BASIC-CONFIG-07: 配置热重载**

- **描述**：管理员修改配置（页面操作或手工编辑）后向 gfrguardd 发送 SIGHUP，daemon 全量重读配置，即时生效，无需重启任何业务进程，业务连续性不受配置调整影响。
- **需求**：
  - 全部配置项支持热生效，无需要求重启 daemon 的参数
- **优先级**：P0

**FR-BASIC-CONFIG-08: 规则库更新**

- **描述**：页面展示当前规则库版本并支持触发更新。规则库目前包含3部分：1.勒索扩展名库；2.评分配置；3.内容检测规则库。
- **需求**：
  - 完整性校验：签名校验 + 哈希校验，校验失败则报错退出，现有规则不变
  - 原子替换：目录级 rename 替换，daemon 任意时刻要么看到完整旧规则、要么看到完整新规则
  - 热生效：替换后向 gfrguardd 发送 SIGHUP 触发 reload；reload 失败回退旧规则并记录日志，升级事故不影响检测主路径
  - 复用既有 SIGHUP 热重载通道，不新增 IPC 机制
- **优先级**：P0

### 3.2. 隔离区

用于设置隔离区的容量上限，并管理隔离区的使用状况及清除操作，勒索功能启用时分配空间。

**FR-QUAR-STORE-01: 隔离区路径**

- **描述**：隔离区路径用于存放在勒索软件检测处理过程中被删除的文件
- **需**

  - 该路径为只读，无法在界面上手动更改
  - 默认值：**/mnt/storage/filer/rguard-store/quarantine** --待定
- **优先级**：P1

**FR-QUAR-STORE-02: 隔离区大小设置**

- **描述**：页面配置隔离区大小，表示存放隔离文件空间的上限。
- **需求**：
  - 以GB为单位设置隔离区的容量上限。最大上限不超过GF2000总容量的10%
  - 输入值必须为1以上的整数
- **优先级**：P0

**FR-QUAR-STORE-03: 隔离区自动清理机制**

- **描述**：隔离区满自动删除旧的隔离文件
- **需求**：
  - 无需配置，隔离区满自动清理最旧的文件
- **优先级**：P0

**FR-QUAR-STORE-04: 隔离区使用率**

- **描述**：页面展示隔离区使用情况（已用容量、隔离区总容量、百分比）
- **需求**：
  - 展示已用容量、隔离区总容量与百分比
- **优先级**：P1

**FR-QUAR-STORE-05: 清空隔离区**

- **描述**：执行此按钮后，隔离区内的所有文件将被删除。未恢复的文件将无法恢复。清除操作需要二次确认，执行后无法撤销。
- **需求**：
  - 一键移除隔离区内全部内容
  - 危险操作，页面二次确认后执行
- **优先级**：P1

**FR-QUAR-STORE-06: 释放隔离区磁盘空间**

- **描述**：执行此按钮后，隔离区所占磁盘空间将被释放，勒索功能关闭才能点击
- **需求**：
  - 释放隔离区所占磁盘空间
  - 危险操作，页面二次确认后执行
- **优先级**：P1

### 3.3. 安全备份区域

设置安全备份区域的容量和单一文件的备份上限，并提供备份区域的清除操作，勒索功能启用时分配安全备份空间。

**FR-BACKUP-STORE-01: 备份区域路径设置**

- **描述**：备份区域路径用于保存保护对象文件的副本
- **需求**：
  - 该路径为只读，无法在界面上手动更改
  - 默认值：**/mnt/storage/filer/rguard-store/backups** --待定
- **优先级**：P1

**FR-BACKUP-STORE-02: 备份区域大小**

- **描述**：页面配置备份区大小，表示存放备份文件空间的上限
- **需求**：
  - 以GB为单位设置备份区域容量的上限。最大上限不超过GF2000总容量的10%
  - 输入值必须为1以上的整数
  - 界面显示备份区域的使用状况（比例及已用容量/备份区总容量）
- **优先级**：P0

**FR-BACKUP-STORE-03: 单文件备份大小限制**

- **描述**：可基于单一文件大小控制是否存入备份区域
- **需求**：
  - 默认为启用，默认的备份文件大小上限为1G。用户可选择任意的文件上限大小
  - 档位 100 MB / 200 MB / 500 MB / 1 GB / 2 GB / 5 GB 可选
  - 若禁用此设置项，所有文件都将成为备份对象，存在写入备份区域超过容量上限的风险
- **优先级**：P1

**FR-BACKUP-STORE-04: 备份区自动清理机制**

- **描述**：页面配置备份区预警阈值，超出后删除旧的隔离文件
- **需求**：
  - 配置最大备份天数，达到上限清理过期文件
  - 配置最大备份比例/大小，达到上限清理最旧文件直至低于阈值
- **优先级**：P0

**FR-BACKUP-STORE-05: 清空安全备份区**

以下为安全/隔离区的关键内部支撑需求（非页面需求）：

**FR-STORE-01: 备份区/隔离区初始化与容量配额**

- **描述**：gfrguardd 启动时在 （XFS）初始化备份区与隔离区两个**独立配额区域**（默认 100 GB / 50 GB）。初始化时探测内核 XFS Project Quota 能力，自动选择实现路径，两条路径汇合到同一挂载点，对上层备份/隔离写入代码完全透明——上层代码不关心底层是 quota 还是 loop 镜像。容量为硬上限：写满即返回错误，由写满策略（3.8）接管后续行为。
- **需求**：
  - 支持 Project Quota：创建 `xx/{backups,quarantine}`，两个目录分别设置 project quota 硬上限（写满返回 EDQUOT），`mount --bind` 进 daemon 挂载命名空间
  - 不支持 Project Quota：创建 `xx/backup.img` 与 `xx/quarantine.img`，分别 `fallocate` 物理预占，格式化为 XFS 后 `mount -o loop`（镜像固定大小天然封顶）
  - 两区配额相互独立：隔离样本增长不得挤占前像空间，反之亦然
  - 落盘统一走 reflink → copy_file_range → read/write 降级
- **优先级**：P0

**FR-STORE-02: 备份区/隔离区安全屏障**

- **描述**：备份区/隔离区经 systemd `PrivateMounts` 挂载，仅在 daemon 挂载命名空间可见；宿主机全局命名空间视角下挂载点始终为空目录。这是前像与隔离样本的最后一道防线：即使勒索进程在 NAS 上获得本地执行能力，也无法触及备份区破坏恢复来源。
- **需求**：
  - 勒索进程（SMB / FTP / 本地，均运行在宿主命名空间）无法遍历、删除前像
  - 隔离区样本不会被宿主侧误执行，也不会经 SMB 共享再次导出（防二次扩散）
  - gfrguard-recover 由 daemon fork + exec 启动，继承同一命名空间获得备份区访问权，不新增授权通道
- **优先级**：P0

**FR-BACKUP-STORE-06: 固定前像保护**

- **描述**：前像是文件被覆盖/截断前的原始内容副本，是勒索攻击后无损恢复的基础。对受保护用户共享中的既有文件，发生覆盖写（O_WRONLY|O_TRUNC）或 truncate 等破坏性写入时，系统**统一**创建前像，不依据文件重要性、进程恶意性或当前会话风险分选择是否备份——先无条件保全现场，再评分定责，前像保护与会话评分在代码模块和数据流上解耦（见 FR-CONSTRAINT-02）。保护范围仅限配置指定的用户共享，OS 关键目录不纳入（见 FR-CONSTRAINT-01）。SMB 通道在 VFS 层执行备份；FTP/云连携/本地通道捕获 fanotify open 事件备份。
- **需求**：
  - 触发条件：samba通道文件被覆盖写入（O_WRONLY|O_TRUNC）、截断或删除时统一创建前像；其他通道通过fanotify open事件触发
  - 备份去重：通过 ctime 判断 30s 窗口内是否已备份
  - 备份流程：优先 reflink（FICLONE CoW 克隆，秒级零空间；需备份区与源同文件系统且支持 reflink，如 XFS reflink=1/btrfs）→ 文件系统不支持时回退 copy_file_range 内核零拷贝 → 再回退 read/write
  - 竞争保护：O_EXCL 创建备份文件，多线程并发安全
  - 备份失败时自动清理中间产物
- **优先级**：P0

### 3.4. 黑白名单

- 对于设置在黑名单中的SMB用户、客户端IP地址，在勒索软件防护功能中跳过检测，直接判定为存在风险，阻断文件访问，并隔离文件
- 对于设置在白名单中的SMB用户、客户端IP地址，在勒索软件防护功能中跳过检测，允许文件访问
- 将勒索软件防护功能设为无效（取消基本设置的"启用"勾选）时，所有功能将失效，因此BL/WL的设置也将失效。（被设置为BL的终端也可以通信）再次启用功能时，已设置的BL/WL将生效
- 仅以IP地址为判断对象，服务（端口号）不作为对象
- 基于IP地址的设置优先于基于SMB用户的设置
- GF2000的检测对象中，BL/WL设置仅限通过SMB的访问
- IP地址与SMB用户的优先级为：IP地址->SMB用户

**FR-BWLIST-01: IP黑名单/白名单设置**

- **描述**：通过设置客户端IP的黑名单/白名单，使用该IP的客户端的文件访问，在勒索软件防护功能检测之前，直接被判定为阻止或允许。
- **需求**：
  - 白名单
    - 将用户的IP设置为白名单时，使用该IP的访问跳过勒索软件防护检测，不在勒索软件防护功能的保护对象范围内
    - 设置的IP为访问GF2000的客户端IP地址
  - 黑名单
    - 将用户的IP设置为黑名单时，使用该IP的访问跳过勒索软件防护检测，直接被阻止
    - 设置的IP为访问GF2000的客户端IP地址
  - 添加IP时，每次仅能输入1项，无法批量添加多个IP项目
  - 在Web界面中，输入的各项目后显示[删除]按钮，可逐个删除已添加的项目
  - IP黑名单与白名单设置冲突时（包含同一IP），优先应用白名单
  - IP黑名单自动添加功能：
    - 被勒索软件防护检测阻止的客户端IP地址，将联动注册到IP黑名单。
    - 对于自动添加到IP黑名单列表中的IP项目，在IP项目后追加"自动"标识符。
  - IP黑（手动）/ 白名单的导入功能，导入文件采用csv文本格式
  - 导入前需检查，格式正确：导入执行前存在的数据将被清除，仅支持全数据导入；格式错误：停止导入
  - 导入数据超过最大输入数量时，保留达到上限为止的导入数据，中断导入处理，并在Web界面显示消息
  - IP黑（手动 / 自动）/ 白名单的导出功能，导出文件采用csv文本格式
  - IP黑名单自动注册发生异常循环时的处理方案（1.扩大自动黑名单上限；2.停samba） -- 待定
- **优先级**：P0

**FR-BWLIST-02: 用户黑名单/白名单设置**

- **描述**：通过设置SMB用户的黑名单/白名单，SMB用户进行文件操作时，在勒索软件防护功能检测之前，直接被判定为阻止或允许。
- **需求**：

### 3.7. 进程常驻监控

本功能旨在Linux运行环境中，使GF2000勒索软件防护的核心进程保持持续可运行的状态，防止因进程异常终止导致防护功能停止。

**FR-MONITOR-01：进程启动时自动启动**

- **描述**：系统启动后，在基本服务初始化完成时，自动启动GF2000勒索软件防护的核心进程。由此使用户无需进行手动启动操作。
- **需求**：
  - 使用systemd服务实现启动时自动启动。服务单元包含在安装包中，安装时执行enable
  - 目标进程的启动顺序依赖于网络服务及文件系统服务，在满足执行所需的前提条件后启动
  - 目标进程即使在勒索软件基本设置中功能为无效的情况下，也会自动启动
  - 系统启动后，确认目标进程处于Active状态。启动失败时，输出错误日志，执行重启处理
  - 重启处理达到上限次数时，视为启动失败，转入告警状态。之后作为常驻监控模块恢复处理的对象
  - 启动时的重试次数及重试间隔可设置。各参数通过后台配置文件管理
  - 不提供面向用户的本功能操作界面。所有处理由后台服务自动执行
  - 服务状态及失败原因记录在本地日志文件中，必要时也输出到系统日志
- **优先级**：P2

**FR-MONITOR-02：进程常驻监控**

- **描述**：通过守护进程持续监控GF2000勒索软件防护核心进程的状态。目标进程异常终止时自动重启，恢复服务功能。
- **需求**：
  - 常驻监控通过systemd服务实现。不引入额外的守护框架，由systemd进行进程的启动及维持
  - 建议在服务单元中设置Restart=always（或on-failure）、RestartSec=5、StartLimitIntervalSec、StartLimitBurst，以抑制异常时的连续重启
  - 必要时启用WatchdogSec，并与Type=notify组合，实现无响应状态的检测及自动恢复
  - 系统启动后，确认目标进程处于Active状态。启动失败时，输出错误日志，执行重启处理
  - 目标进程异常终止时，systemd按照重启策略自动重启。连续失败次数达到阈值时视为失败状态，输出告警
  - 不在Web界面进行状态显示。状态确认通过systemctl、journalctl等运维命令实施
- **优先级**：P2

### 3.10. 许可管理

许可证管理用于显示勒索软件防护功能的许可证状态，并通过激活按钮与Licenses服务器联动获取可用的许可证，设备激活时，附加设备的序列号查询有效的许可证。

**FR-LICENSE-01: 许可激活**

- **描述**：防勒索功能采用许可控制。设备出厂默认为未激活状态，全部防护能力（四通道监控、评分、阻断、备份、恢复）处于关闭状态；管理员在许可管理页面通过"激活"操作导入许可后，防勒索功能方可启用。许可校验失败（格式非法、签名不匹配、已过有效期）时激活操作被拒绝并提示原因，系统保持未激活状态不变。未激活状态下防护完全不生效，且不对业务产生可感知的性能开销。
- **需求**：
  - 点击激活按钮后，设备向Licenses服务器发送查询请求，请求中包含设备的序列号。序列号的获取方法由SAXA提供，NEO不限定具体的读取实现
  - 服务器返回可用的许可证时，设备应用许可证，并更新状态和有效期限的显示
  - 服务器没有可用的许可证时，保持当前状态，显示"没有可用的License"
  - 无法连接服务器时，保持当前状态，显示"无法连接服务器。请确认网络设置"
  - 激活按钮可重复点击，即使已激活也不禁用
  - 再次激活用于追加购买场景，设备再次向服务器查询是否存在新的可用许可证
  - 存在新许可证时，按照服务器策略更新有效期限（例：延长至新的有效期限日）。没有新许可证时，保持原状态
  - 每次激活需记录请求时间、序列号、激活结果
  - 设备更换时，许可证迁移在许可证服务器上完成许可证的替换
  - 旧设备定期确认许可证状态。检测到删除时，从首次检测日起15天后删除。15天后正式删除后，功能将无法使用
  - 新设备开始运行后，点击“自动获取”即可同步许可证。新设备获取许可证后即可正常使用功能
  - 许可证到期时，功能停止，规则更新停止，对许可证服务器的许可证检查也停止
- **优先级**：P1

### 3.11. 边界与容量限制

各项容量上限与写满行为的统一定义，页面条目中的相关设置以本节为准。

**FR-LIMIT-01: 备份区写满策略**

- **描述**：备份区自动清理机制，保证备份区不会写满。支持时间与百分比两个维度且均可配置：按时间清理超过保留期限的旧前像，按百分比在用量超过阈值时清理最旧的项目。备份区存放的是恢复生命线，策略目标是"日常不写满"，而非写满后循环覆盖。
- **需求**：
  - 支持按时间维度配置自动清理
  - 支持按百分比维度配置自动清理
  - 清理对象为最旧的备份项目
- **优先级**：P0

**FR-LIMIT-02: 备份区大小策略**

- **描述**：约束备份区容量的可调范围，防止过度配置挤占业务存储。系统保留空间 >= max_disk × 5%，最大备份区 <= max_disk × 15%；用户手动配置容量时页面需提示可扩容空间范围 (1, max)，其中 max = min(disk_left − max_disk × 5%, max_disk × 15% − cur_size)。
- **需求**：
  - 系统保留空间 >= max_disk × 5%
  - 备份区容量上限 <= max_disk × 15%
  - 手动配置时提示可扩容范围 (1, max)，max = min(disk_left − max_disk × 5%, max_disk × 15% − cur_size)
- **优先级**：P0

**FR-LIMIT-03: 隔离区写满策略**

- **描述**：隔离区自动清理机制，保证隔离区不会写满，在用量超过阈值时清理最旧的项目。
- **需求**：
  - 支持自动清理，无需手动配置
  - 清理对象为最旧的备份项目
- **优先级**：P0

**FR-LIMIT-04: 隔离区大小策略**

- **描述**：约束隔离区容量的可调范围，防止过度配置挤占业务存储。系统保留空间 >= max_disk × 5%，最大隔离区 <= max_disk × 15%；用户手动配置容量时页面需提示可扩容空间范围 (1, max)，其中 max = min(disk_left − max_disk × 5%, max_disk × 15% − cur_size)。
- **需求**：
  - 系统保留空间 >= max_disk × 5%
  - 隔离区容量上限 <= max_disk × 15%
  - 手动配置时提示可扩容范围 (1, max)，max = min(disk_left − max_disk × 5%, max_disk × 15% − cur_size)
- **优先级**：P0

**FR-LIMIT-05: 单文件前像大小上限**

- **描述**：单个文件的前像大小支持配置上限，防止单个超大文件耗尽备份区。默认**不限制**；可选档位 100 MB / 200 MB / 500 MB / 1 GB / 2 GB / 5 GB。超限文件的处理语义见 FR-BACKUP-STORE-02（跳过前像、照常评分、标记"不受前像保护"）。
- **需求**：
  - 默认不限制
  - 可选档位 100 MB / 200 MB / 500 MB / 1 GB / 2 GB / 5 GB
- **优先级**：P1

**FR-LIMIT-06: 名单容量上限**

- **描述**：约束四类名单的最大条目数，保证匹配开销与配置体积有界。IP 黑名单：手动 64 条 + 自动 64 条，自动条目超上限时覆盖最旧（FIFO）；IP 白名单：64 条；用户黑名单 / 用户白名单：各 64 条。
- **需求**：
  - IP 黑名单：手动 64 条 + 自动 64 条，自动条目超上限 FIFO 覆盖最旧
  - IP 白名单：上限 64 条
  - 用户黑名单 / 用户白名单：各上限 64 条
- **优先级**：P0

**FR-LIMIT-07: 例外路径条目上限**

- **描述**：例外文件 / 例外文件夹条目数需要限制，防止性能内存问题。
- **需求**：
  - 例外文件 / 例外文件夹条目数限制为 64
- **优先级**：P0

**FR-LIMIT-08: 例外路径长度上限**

- **描述**：例外文件 / 例外文件夹路径长度需要限制为 4096，防止性能内存问题。
- **需求**：
  - 例外文件 / 例外文件夹路径长度限制为 4096 字节
- **优先级**：P0

**FR-LIMIT-09: 阻断事件显示上限**

- **描述**：阻断链接记录页面仅显示最近 192 条阻断事件，保证列表加载性能；更早的记录通过筛选与 CSV 导出获取。
- **需求**：
  - 显示最近 192 条阻断事件
- **优先级**：P0

**FR-LIMIT-10: 勒索事件显示上限与 CSV 归档**

- **描述**：events 表仅保留**最近 10000 条且不超过 30 天**的事件，防止数据库无限膨胀；每日归档任务将超出保留窗口的事件导出为 CSV 并压缩成 zip，后删库，历史数据不丢失且可离线查阅。
- **需求**：
  - 当日无事件：不生成 CSV，输出 1 条系统日志（当日无事件，跳过归档）
  - 当日事件 ≤ 10000：生成 1 个 CSV，输出 2 条系统日志（已处理事件数 / 未处理事件数）
  - 当日事件 > 10000：按每文件最多 10000 条拆分多个 CSV，每个 CSV 各输出 2 条系统日志
  - CSV 压缩存储
  - 归档只删除事件索引（events 及关联行），不动前像；前像生命周期由 FR-LIMIT-01 独立管理
- **优先级**：P0

**FR-LIMIT-11: 隔离事件显示上限与 CSV 归档**

- **描述**：隔离事件采用与勒索事件相同的保留与归档策略（见 FR-LIMIT-10）。
- **需求**：
  - 同 FR-LIMIT-10
- **优先级**：P0

### 3.12 其他

**FR-DAEMON-01: 四通道事件接收与生命周期管理**

- **描述**：gfrguardd 以 systemd 服务方式运行，是四通道检测的统一引擎，通过两种机制接收事件：SMB 通道经 Unix Socket DGRAM 接收 VFS 模块上报（fire-and-forget）；FTP / 云连携 / 本地通道共用 fanotify fd（FAN_CLASS_CONTENT），内核同步阻塞文件 open 操作等待判定。统一引擎保证四通道共享同一套会话追踪、评分与阻断逻辑，行为一致。
- **需求**：
  - epoll 单线程事件驱动 (socket + fanotify_fd + timerfd + signal)
  - fanotify 事件按路径前缀分发到对应 handler
  - SIGHUP 热重载，SIGTERM/SIGINT 优雅退出
  - 异常退出后 systemd 自动重启
- **优先级**：P0

**FR-DAEMON-02: 会话级行为追踪（统一 session key 格式）**

- **描述**：按通道维护会话级行为计数器，将勒索行为的时间相关性在会话维度聚合——单个文件操作可能是无害的，同一会话内的批量操作序列才是攻击特征。session key 格式全通道统一为 `username@client_ip`，由公共骨架（rguard_make_session_key）在通道 resolve 之后统一推导——通道只负责填充 username / client_ip 两个字段，不各自拼 key。各通道字段语义：
  - SMB：`user@ip`（VFS 上报真实会话用户与客户端 IP）
  - FTP：`user@ip`（三级上下文解析；全部失败时回退 `ftp@unknown`）
  - 云连携：`cloud@<task_name>`（client_ip 字段携带 rclone task_name；非 IP 格式被 inet_pton 闸门挡住，不会写入 blocked 文件）
  - 本地：`<comm>@local:<pid>:<starttime>`（client_ip 字段携带进程实例标识，starttime 防 PID 复用后会话串号）
- **需求**：
  - 1024 槽哈希表（FNV-1a + 线性探测）四通道共存，key 由骨架统一推导，通道间靠字段内容天然隔离，辅以 source_type 路由
  - 双窗口机制：短窗口(10s)重置操作计数器，长窗口(30s)重置会话整体状态；云连携通道独立窗口（默认 60s/180s）适配云 API 事件节奏
  - 追踪 11 项指标：modified / rename / delete / touched_dirs / ext_change / ransom_ext / high_entropy / rule_match / content_same / risk_score / risk_level
- **优先级**：P0

**FR-DAEMON-03: 内容信号分析**

- **描述**：对内容进行 Shannon 熵采样和 YARA 规则匹配，结果作为会话级证据参与行为风险评分。为规避专利边界（详见 FR-CONSTRAINT-03），不逐文件标记 damaged/corrupted/encrypted 状态，不累计"损坏/加密文件数"，不按"某类文件数量≥N"的方式阻断。
- **需求**：
  - 触发时机：熵分析在写入过程中采样（SMB=OPEN/WRITE/TRUNCATE，fanotify=CREATE/MODIFY，采样文件头 8 KiB）；YARA 规则匹配在文件句柄关闭后执行（SMB=CLOSE，fanotify=CLOSE_WRITE），全文件扫描需要完整内容
  - 会话去重：同一会话首次命中某内容信号后，该会话后续文件不再执行对应扫描；窗口重置清空命中状态后扫描自动恢复
  - 评分语义：高熵为会话级布尔信号，首次命中置位、固定权重只加一次；YARA 为定性证据，任一命中直接把会话提升至 CRITICAL，不参与加权求和
- **优先级**：P0

**FR-DAEMON-04: 勒索扩展名检测**

- **描述**：在 RENAME 和 NEW_FILE 事件中检测已知勒索扩展名（.locked / .encrypted 及家族专属后缀等）。批量将文件重命名为勒索扩展名是勒索软件的标志性行为，命中作为定性证据参与评分，是识别"批量重命名加密"攻击模式的关键信号。
- **需求**：
  - RENAME 事件比对目标扩展名，NEW_FILE 事件比对文件扩展名
  - 命中置 ransom_ext 标记并参与评分
- **优先级**：P0

**FR-DAEMON-05 加权风险评分**

- **描述**：多维加权评分 (0-100)，三级阈值：normal(0-30) / Suspicious(30-80) / critical=(80-100)，将会话追踪的行为指标与内容信号汇聚为单一风险分，驱动告警与阻断决策。评分以文件操作行为指标为主，内容信号为辅，不基于"损坏文件数"或"加密文件数"驱动阻断。
- **需求**：
  - 评分范围 0-100，阈值 warn=30 / high=60 / critical=80
  - 行为指标加权求和，内容信号按 FR-DAEMON-03 语义参与
- **优先级**：P0

**FR-DAEMON-06: 会话阻断执行**

- **描述**：会话风险评分达到 CRITICAL 时，根据 source_type 执行差异化的阻断动作，即刻切断攻击通道。各通道阻断方式与其协议特性匹配：SMB/FTP 面向会话与连接，云连携面向定时任务，本地面向进程；阻断动作本身即产生阻断链接记录。
- **需求**：

| 通道   | 阻断方式                                                               |
| ------ | ---------------------------------------------------------------------- |
| SMB    | 写 blocked 文件 + smbcontrol smbd close-share                          |
| FTP    | FAN_DENY + kill vsftpd child (SIGTERM) + 写 blocked 文件               |
| 云连携 | FAN_DENY + neo-croner delete --task-name + kill 进程树 + 保存配置到 DB |
| 本地   | FAN_DENY + SIGKILL                                                     |

- **优先级**：P0

**FR-VFS-01: SMB 文件操作实时监控**

- **描述**：VFS 模块 vfs_gfrguard.so 以 Samba 标准 VFS 插件形式加载，不修改 Samba 源码，实时拦截 SMB 协议层面的关键文件操作，包括文件打开、写入、截断、重命名、删除和创建目录。拦截对 SMB 客户端完全透明，模块任何异常都不得影响 Samba 服务稳定性。
- **需求**：
  - 操作拦截对 SMB 客户端透明，不影响正常的文件 I/O 流程
  - 当检测到会话已被阻断时，拒绝后续文件操作并返回访问拒绝 (EACCES)
  - 发生错误时静默回退到正常的文件操作路径，不影响 Samba 服务稳定性
  - 排除 O_APPEND 模式（内核强制追加写入，非勒索攻击向量）
  - 覆盖 ftruncate 绕过防御（O_APPEND open + ftruncate 截断）
- **优先级**：P0

**FR-VFS-02: 文件操作事件上报**

- **描述**：VFS 模块通过 AF_UNIX SOCK_DGRAM 以 fire-and-forget 模式将文件操作事件发送到 gfrguardd，不等待应答：daemon 繁忙或异常时 SMB 业务 I/O 不受影响，事件上报永远不成为业务路径上的阻塞点。
- **需求**：
  - source_type 固定为 RGUARD_SOURCE_SMB
  - 发送失败最多重试 3 次（EAGAIN 间隔 500µs），仍失败则丢弃事件
- **优先级**：P0

**FR-VFS-03: 相同内容覆盖识别**

- **描述**：正常批量部署（相同配置文件/固件/安装包覆盖多个目录）与勒索批量加密在行为特征上高度相似，是最主要的误报源。文件关闭时通过 FNV-1a hash 比对新写入内容与前像内容，内容完全相同则判定为正常部署行为，抑制风险评分，保证故事二"正常业务操作不受影响"。
- **需求**：
  - 触发时机：gf_close()，仅对 is_risky 文件（含备份成功/失败/新建 RANSOM_EXT）
  - 内容相同时设 CONTENT_SAME 标记以抑制风险评分
- **优先级**：P0

**FR-VFS-04: 会话阻断检查**

- **描述**：SMB 通道在每个文件操作前，通过 stat mtime 缓存检查 blocked 文件，命中则返回 EACCES 拒绝访问。基于 mtime 的缓存避免每次操作都读取 blocked 文件内容，阻断检查开销可控，不影响正常会话的 I/O 性能。
- **需求**：
  - 每个文件操作前执行阻断检查，命中 blocked 返回 EACCES
  - 缓存基于 stat mtime，blocked 文件变更后缓存自动失效
- **优先级**：P0

**FR-CLOUD-01: 云同步文件操作同步拦截**

- **描述**：通过 fanotify FAN_OPEN_PERM 在内核层同步阻塞 rclone 进程的 open() 操作，在云端加密文件落盘前完成判定。云同步的事件节奏由云 API 轮询驱动，与 SMB/FTP 的实时会话不同，会话窗口与阻断方式均按任务维度适配（见 FR-DAEMON-02 / FR-CLOUD-02）。
- **需求**：
  - 监控范围：rguard-policy.json 中 cloud_sync.tasks[].local_path 配置的 rclone 本地目录
  - 任务识别：解析 rclone 进程的 /proc/PID/cmdline，找到 `remote:path` 格式参数，取 `:` 前部分作为 task_name
  - session_key = `cloud@<task_name>`（如 `cloud@onedrive_1`）
  - 排除 rclone 临时文件（`.partial~`、`.tmp`、`.rclone-tmp`）
- **优先级**：P1

**FR-CLOUD-02: 云同步任务阻断**

- **描述**：云连携通道 CRITICAL 时 FAN_DENY + kill rclone 进程树 + neo-croner delete --task-name 删除定时任务，防止 neo-croner 自动重启同步导致加密文件持续从云端扩散到本地。阻断前通过 neo-croner query 保存任务配置（expression + command）到 DB，供后续恢复（FR-CLOUD-03）完整重建任务。
- **需求**：
  - 阻断前通过 neo-croner query 保存任务配置（expression + command）到 DB
  - 删除定时任务防止 neo-croner 自动重启同步
  - session 独立于 SMB/FTP（key 格式 `cloud@<task_name>`，不写 blocked 文件）
- **优先级**：P1

**FR-FTP-01: FTP 文件操作同步拦截**

- **描述**：通过 fanotify FAN_OPEN_PERM 在内核层同步阻塞 vsftpd 子进程的 open() 操作，在文件被覆盖前完成备份和风险判定——判定放行后文件才会被真正打开，实现"先判定后写入"。
- **需求**：
  - 监控范围：rguard-policy.json 中 ftp.monitor_paths 配置的 FTP 目录，**递归覆盖整棵目录树**（nftw 逐目录 mark；新建/移入目录动态补 mark）
  - 拦截操作：覆盖写入（STOR/APPE → O_WRONLY|O_TRUNC）、新建文件（O_CREAT）
  - 检测操作（notify 异步事件，FAN_REPORT_DFID_NAME group，与 SMB VFS 通道对齐）：
    - 覆盖写/截断：FAN_MODIFY → WRITE|RISKY（truncate 经 ATTR_SIZE→FS_MODIFY 同样覆盖）
    - 新建文件/目录（mkdir）：FAN_CREATE → OPEN|NEW_FILE（勒索后缀检查 + created_files 追踪）
    - 删除：FAN_DELETE → DELETE
    - 重命名：FAN_RENAME→ RENAME（携带 new_name，支持 EXT_CHANGE/RANSOM_EXT 检测）
    - 关闭：FAN_CLOSE_WRITE → CLOSE（YARA入口）
  - 固有限制（fanotify 能力边界）：delete/rename/mkdir 无 perm 事件，仅能事后检测+阻断；unlink 不经 open，无删除前备份
  - 上下文关联（三级策略）：① `/proc/PID/cmdline` 直接提取 IP+User；② socket-inode 映射获取 IP；③ `/proc/PID/status` → UID → getpwuid 获取 User
    - 支持本地用户、匿名用户、虚拟用户（通过 cmdline 解析）
  - 无需 PID 表——fanotify FAN_OPEN_PERM 同步阻塞进程，/proc 解析在事件处理时完成
- **优先级**：P2

**FR-FTP-02: FTP 场景风险阻断**

- **描述**：FTP 通道 CRITICAL 时 FAN_DENY 拒绝当前 open + SIGTERM 终止 vsftpd 子进程 + 写 blocked 文件。阻断与 SMB 通道互通：同一 user@ip 在两个通道间共享阻断状态，防止攻击者被单通道阻断后切换通道绕过防护。
- **需求**：
  - 阻断与 SMB 通道互通（同一 user@ip 在两个通道间共享阻断状态）
  - vsftpd 子进程终止后，客户端后续 FTP 命令无法执行
- **优先级**：P2

**FR-LOCAL-01: NAS 本地进程文件操作同步拦截**

- **描述**：通过 fanotify FAN_OPEN_PERM 监控受保护目录下所有本地进程的文件操作，以 PID 为粒度追踪。本地通道面向"NAS 自身被植入恶意代码"的场景（备份脚本被篡改、第三方服务被入侵），系统进程经白名单直接放行以避免自我干扰。
- **需求**：
  - 监控范围：rguard-policy.json 中 local.monitor_paths 配置的本地目录，**递归覆盖整棵目录树**（同 FR-FTP-01）
  - 检测事件覆盖与 FTP 通道一致（见 FR-FTP-01）：MODIFY / CREATE（含 mkdir）/ DELETE / RENAME / CLOSE_WRITE
  - session_key = `<comm>@local:<pid>:<starttime>`（统一 `username@client_ip` 格式：comm 填 username 字段，`local:<pid>:<starttime>` 填 client_ip 字段），starttime 取自 `/proc/PID/stat` 防 PID 复用
  - 进程名白名单（smbd / systemd / sshd / rclone / vsftpd / gfrguardd 等）→ FAN_ALLOW 直接放行
  - 白名单进程跳过所有检测和评分，不做备份
- **优先级**：P2

**FR-LOCAL-02: 本地恶意进程阻断**

- **描述**：本地通道 CRITICAL 时 FAN_DENY 拒绝当前操作 + SIGKILL 直接终止恶意进程，不给勒索进程继续执行加密的机会。本地进程无会话概念，阻断以进程为粒度一次到位。
- **需求**：
  - FAN_DENY 拒绝当前文件操作
  - SIGKILL 终止恶意进程
- **优先级**：P2

## 4. 技术约束

**FR-CONSTRAINT-01: 保护范围**

GFRGuard 仅保护经由明确配置的 SMB 共享、FTP 目录、云同步目录及本地监控目录暴露的**对外用户共享数据**。以下目录和对象**不在保护范围内**，不纳入前像保护和事件监控：

- 操作系统启动文件（`/boot`）
- 系统配置文件（`/etc`，Samba 核心配置除外）
- 系统可执行文件（`/bin /sbin /usr/bin /usr/sbin`）
- 系统动态库（`/lib /usr/lib /lib64 /usr/lib64`）
- 系统数据库和启动配置
- GF2000 系统程序和关键服务文件

**FR-CONSTRAINT-02: 固定前像**

对受保护用户共享中的既有文件，覆盖写和 truncate 等破坏性写操作**依照写入类型统一创建前像**。前像生成逻辑不依据文件重要性、进程可信度/恶意性或当前会话风险评分选择性触发。前像保护与后续的反勒索会话评分在代码模块和数据流上解耦。

**FR-CONSTRAINT-03: 内容信号与计分规则**

内容信号定位与计分方式共同构成专利规避边界，二者不可拆分：

- **触发时机**：熵分析在写入过程中采样（文件头 8 KiB）；YARA 规则匹配在文件句柄关闭后触发（CLOSE / CLOSE_WRITE，全文件扫描需要完整内容）；
- **不计数、不判定**：系统不逐文件标记 damaged/corrupted/encrypted 状态，不累计"损坏文件数量"，不按"损坏文件数≥N"触发阻断。高熵为会话级布尔信号——首次命中置位、固定权重只加一次；YARA 为定性证据——任一命中直接把会话提升至 CRITICAL，不参与加权求和；
- **会话级去重**：同一会话首次命中某内容信号后，该会话后续文件不再执行对应扫描；窗口重置清空命中状态后扫描自动恢复；
- **阻断多维性**：任何单一行为计数维度（修改 / 重命名 / 删除 / 目录扩散）的加权贡献不得单独达到 CRITICAL；CRITICAL 必须由至少两个独立行为维度、或维度评分叠加定性证据（YARA / 勒索扩展名）共同达到。
